# Goal

Merge `ChessRenderChild` (list) and `TreeRenderChild` into a single `ChessRenderChild` using the tree data model. The UI layout becomes:

```
┌──────────────────────────────┐
│ Board                         │
├──────────────────────────────┤
│ Toolbar                       │
├──────────┬───────────────────┤
│ 走法列表  │  分支图 (SVG Tree) │
│ (List)   │  + eval sidebar   │
│          │  + slider         │
├──────────┴───────────────────┤
│ 评论框 (Comments textarea)    │
└──────────────────────────────┘
```

List and Tree SVG are **side-by-side** in the tools area. Comments textarea spans the full width below.

# Design

## 1. Type Changes — `types.ts`

- **Remove** `IListHost` entirely
- **Add** to `ITreeHost`:
  - `options: IOptions` (was only on IListHost)
  - `mode: "list" | "tree"` (display mode, determines if list is shown)

## 2. Module System — `module-system.ts`

- **Remove**: `ListModules`, `registerListModule`, `createListModuleRegistry`, `destroyListModuleRegistry`

## 3. Source.ts

- **Remove** `"list"` case; always use tree parsing with `prepareSource()`
- Store `host.options = opts` from `prepareSource()`

## 4. Tree/Actions.ts

- Add `clickstep` handler: step index → node in `currentPath` → emit `node-click`

## 5. Tree/ChessBoard.ts

- Pass `mode: host.mode` and `options: host.options || {}` to Svelte component

## 6. Tree.svelte — Modified Layout

Current `.tree-container` layout:
```
.tree-container (flex column)
  .svg-wrapper (flex: 1)
    .eval-sidebar (absolute, left)
    svg.tree-svg
    .toolbar (absolute, bottom-left)
    .slider (absolute, right)
  textarea (comments)
```

New layout:
```
.tree-container (flex column)
  .tools-row (flex row, flex: 1)
    .move-list (scrollable, left side)       ← NEW (from List.svelte)
    .svg-wrapper (flex: 1, right side)
      .eval-sidebar (absolute, left)
      svg.tree-svg
      .toolbar (absolute, bottom-left)
      .slider (absolute, right)
  textarea (comments, full width below)
```

**List section** (`.move-list`):
- Derives `moves` from `currentPath` + `nodeMap` (filter nodes with `move !== null`)
- Derives `currentStep` from `currentPath.indexOf(currentNode.id)`
- Click emits `node-click` with the node ID at that step index
- Scroll-to-active behavior (same as current List.svelte)
- Only shown when `mode === "list"` (or always shown? — to be confirmed)

**SVG section** (`.svg-wrapper`):
- Unchanged — same D3 tree, eval sidebar, slider, toolbar

**Comments textarea**:
- Same as before, full width below the tools row

### List data derivation

```typescript
let moves = $derived(
  currentPath
    .map(id => nodeMap.get(id)!)
    .filter(n => n && n.move !== null)
);
let currentStep = $derived(currentPath.indexOf(currentNode?.id ?? ""));

function onClickStep(step: number) {
  if (step === 0) {
    eventBus.emit("node-click", currentPath[0]);
  } else {
    const nodeId = currentPath[step];
    if (nodeId) eventBus.emit("node-click", nodeId);
  }
}
```

## 7. Tree/Chess.svelte

Add `mode` and `options` props. Pass them to Tree component:

```svelte
interface Props {

  options: IOptions;

<Tree {nodeMap} {eventBus} {currentNode} {currentPath} {mode} {settings} />
```

## 8. Tree/Toolbar.svelte

Add `options` prop. Disable save button when `options.protected`:

```svelte
let isprotected = $derived(options?.protected || false);
// Save button: disabled when isprotected
```

## 9. ChessRenderChild

New unified RenderChild with `mode` parameter:

```typescript
export class ChessRenderChild extends MarkdownRenderChild {
  mode: "list" | "tree";
  constructor(containerEl, ctx, source, plugin, mode = "tree") {
    super(containerEl);
    this.mode = mode;
    containerEl.classList.add("tree-codeblock");
    createTreeModuleRegistry(this);
  }
  // ...
}
```

## 10. main.ts

```typescript
import { ChessRenderChild } from "./renderChild/ChessRenderChild";

// chess code blocks → list mode
for (const name of codeBlockNames.chess) {
  this.registerMarkdownCodeBlockProcessor(name, (source, el, ctx) => {
    ctx.addChild(new ChessRenderChild(el, ctx, source, this, "list"));
  });
}

// tree code blocks → tree mode
for (const name of codeBlockNames.tree) {
  this.registerMarkdownCodeBlockProcessor(name, (source, el, ctx) => {
    ctx.addChild(new ChessRenderChild(el, ctx, source, this, "tree"));
  });
}
```

## Risks And Compatibility

- **Tree.svelte is already 1200 lines**: Adding list section adds ~80 more lines. Acceptable.
- **List visual**: Must match current List.svelte appearance
- **Save behavior**: Always full tree; "save current line" option removed
- **`prepareSource()` always applied**: Tree mode also processes option lines — harmless
